# Native Runtime 0.15.6

A completed model/tool iteration can reach its local context limit while new input is still queued. Runtime now ends that turn through the existing `max_turn_requests` / `active_turn_context_capacity` outcome when those inputs have never been forwarded. It handles both a full active continuation and pending input that would overflow an otherwise fitting window.

Every queued input keeps its original identity, content and order in a `notAccepted` receipt with the capacity reason. It is not added to model history, marked handled, or replayed. The admission boundary closes atomically; remotely submitted or uncertain inputs retain their existing failure handling. Stop still wins, and configured limits remain unchanged.

Content-free diagnostics identify the overflowing boundary, byte measurements, input-state counts and any condition that prevented a normal capacity stop. A closed runtime boundary does not certify asynchronous domain effects or authorize a task to continue. Saved history, model settings, credentials and work authority are unchanged.

Disposable provider/MCP regressions reproduce both failures on 0.15.5 and verify receipt preservation, reload, cancellation and uncertain outcomes on this release. Native packages retain the six-platform packaging and unsigned-preview limitations documented in 0.15.4. Live-provider and domain recovery qualification remain separate from these fixtures.
