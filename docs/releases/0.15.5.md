# Native Runtime 0.15.5

A long turn can fill its working context after completed tool calls even though older turns have already been compacted. Runtime now reports this specific, settled local capacity stop through its existing `max_turn_requests` outcome, with `stopCause: active_turn_context_capacity`, instead of a generic backend failure. An authorized client can continue in the same session with a fresh prompt; the saved history and tool receipts remain intact.

This does not retry a prompt, repeat a tool, increase a limit or declare the task complete. Pending steering, unknown tool outcomes, cancellation, oversized initial requests and unrelated provider failures retain their distinct handling. Diagnostics now distinguish counted context bytes from serialized JSON size.

Six process regressions cover the actual ACP/provider/tool boundary, including same-session reload, Stop and uncertain outcomes. Native packages retain the six-platform packaging and unsigned-preview limitations documented in 0.15.4. This release does not change model selection, credentials or configured work authority.
