# Runtime 0.15.13

An owner-added or removed provider-hosted tool can leave a saved model choice
bound to its earlier configuration. Runtime now provides an explicit local-owner
`reconcile-native-tools` command to restore that existing session's compatibility
without reverting the shared configuration or replacing the session.

Preparation produces a reviewable plan containing the exact old and new tool
declarations. Application requires the original configuration evidence and
unchanged session/configuration bindings, holds the existing locks, and records
one atomic owner receipt. Provider, account, model and other native-capability
changes remain refused. Inspect the operation receipt after a lost response.

The operation preserves history, provider binding, input uncertainty and other
sessions. It does not call a provider, run tools, load a session or resume work.
Ordinary configuration changes and ACP model choices retain their existing
checks; reconciliation is never automatic. See the
[owner procedure](../provider-identity.md#reconcile-a-provider-hosted-tool-change).

There is no history-schema, dependency or ACP-profile change in this release.
Existing binaries can read the reconciled saved-choice format.
