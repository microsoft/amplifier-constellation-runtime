# Native Runtime 0.15.1

Conversation updates during an active prompt no longer let extractive
compaction discard that prompt's fresh tool results. The engine supplies the
actual controlling-prompt boundary, so compaction can shorten older history
while retaining the current request, observations and steering inputs together.

This also applies to the extractive preparation used before an initial
provider-native compaction. Provider-native checkpoint semantics, saved
transcripts, input receipts, selected models and permissions remain unchanged.
An oversized active continuation fails visibly instead of losing evidence.
Completed turns become eligible for normal compaction on the next prompt.

Regressions reproduce the lost observations on 0.15.0 and check preservation on
the actual ACP-to-provider path after several steering inputs. They use a
disposable session and deterministic local provider, not a production model or
world. Keeping evidence available does not certify the model's report or claim
that all reasoning and verbosity errors are resolved.
