# Native Runtime 0.15.2

An agent can show a requested saved image in its current conversation without
asking for a second approval. `workspace_attach_image` is response output in
read-only, ask and workspace modes. It reads an image from the session's already
granted workspace and emits ordinary ACP image content to the current client.
This intentionally replaces the previous write-permission classification.

The tool cannot select another audience, fetch a remote URL or alter the file.
Workspace confinement, regular-file and image-format validation, and the 2 MiB
limit remain enforced. Viewing an image or receiving one from MCP still does not
publish it. Loading saved history does not emit another outgoing attachment.
File writes, commands and external MCP effects retain their existing permissions.
Experience adapters continue to own audience and attachment delivery.

Actual ACP tests cover all three modes, unchanged write/MCP refusals, explicit
attachment versus observation, invalid paths and images, and reload without
republication. They use fresh disposable sessions and local provider fixtures;
they do not claim live voice or platform delivery coverage.
