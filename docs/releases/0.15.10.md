# Runtime 0.15.10

Runtime can now describe approval requests to a supporting Agent Instance so an
owner can remember a matching approval across that agent’s chats. The optional
profile binds the actual operation, arguments, resource grants and tool
connection. Changed content, endpoint or effective scope requires a new match.
Descriptions identify the target without copying file contents, command
arguments or credentials into remembered rules.

Instance owns the saved policy and its controls. Runtime does not add another
approval cache or switch its permission mode. Existing schema validation,
read-only mode, workspace boundaries, cancellation and work budgets remain in
force. The same descriptors cover the Copilot path, while Rust continues to own
tool execution and permission checks. Peers that do not negotiate the profile
keep the existing current-request behavior.

Use Instance 0.22.9 or a compatible implementation for the shared controls.
Automatic approval is an explicit owner setting, not an upgrade default.
