# Runtime 0.10.0

New messages can join active work without cancelling tools or resetting a task's
limits. Native OpenAI generation uses GPT-6 Responses WebSockets and steering;
other providers incorporate ordered messages at their next legal model call.

Durable input receipts distinguish admission, remote acceptance, incorporation,
rejection and uncertain transport outcomes. Session reload preserves these
receipts; uncertain work requires explicit review instead of automatic replay.
Pipelined arrivals retain their order, approval waits survive new input, and
context/call/time limits apply across all successor responses.

The model catalog selects current classes. Older native GPT execution and
explicit-budget Claude thinking are no longer supported. Existing installations
and saved provider bindings are not silently migrated. Optional ACP steering
requires support from the experience and any intermediate Instance relay;
ordinary ACP clients remain compatible.

Validation includes real ACP subprocesses and WebSocket fixtures, ordered-input
checks across seven HTTP provider routes, native tools/media/reload regressions,
and a disposable live GPT-6.1-sol steering check. Fixture success does not prove
account access to every cataloged model.
