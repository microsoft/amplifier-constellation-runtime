# Native Runtime 0.15.0

ACP clients can select an installation-approved model and reasoning effort through standard session configuration options. Choices are saved per session and survive reconnection and process restart. Installation defaults and other sessions remain unchanged.

The owner configures `model_options` in `runtime.json`. Choices retain the provider, endpoint, account selector, credentials and permissions; an update does not enable extra models or alter existing selections. See [configuration and history limits](../acp-optional-capabilities.md#session-model-and-reasoning-choices).

Model changes support empty or ordinary text histories. Sessions containing tool, media or opaque provider history refuse a model change without altering their history. Reasoning controls remain independently available when offered by the installation. Active turns, unavailable saved choices and changed provider routes fail visibly. No history migration or automatic replacement session is performed.

The exact implementation passed 85 Rust and 92 focused Python checks. Independent unchanged ACP v1 TCK profiles passed 71 tests with three skips for the OpenAI fixture and 72 with two skips for Gemini, including all 31 mandatory requirements. Both profiles used trusted-local-client; the restricted default retains its local MCP policy. Separate official SDK checks verified model/reasoning on the local provider wire, persistence, isolation and unchanged history/receipts. These are deterministic provider tests, not real-model quality or account-entitlement qualification.

This release also includes the previously merged local-provider and completed-conversation fixes through the 0.14 development line. Existing model/provider configuration, session bindings and work authority remain owned by each installation.
